 项目开发文档：AI智能知识库助手
1. 项目概述
1.1 项目名称
AI-Powered Personal Knowledge Base (个人智能知识库助手)

1.2 项目目标
开发一个端到端的AI全栈应用，支持用户上传多种格式文档（PDF、图片、音频），通过RAG（检索增强生成）技术实现智能问答和内容摘要。

1.3 核心功能
用户上传PDF/图片/音频文件

后台自动解析并向量化存储

基于文档内容的智能问答（带流式输出）

跨文档摘要生成

文件管理（列表/删除）

2. 技术栈
前端
框架: Next.js 14 (App Router)

样式: Tailwind CSS + shadcn/ui

状态管理: Zustand (轻量级)

HTTP客户端: Axios

后端 (Python)
Web框架: FastAPI (异步支持)

ORM: SQLAlchemy 2.0 + Alembic (数据库迁移)

数据库:

PostgreSQL (存储用户/文件元数据)

ChromaDB (向量存储，本地持久化)

AI/ML库:

LangChain (RAG流程编排)

OpenAI SDK / 智谱SDK (LLM调用)

Whisper (音频转文字)

PyPDF2 / pdfplumber (PDF解析)

Pillow (图片预处理)

异步任务: Celery + Redis (大文件处理)

文件存储: 本地文件系统 (开发环境) / MinIO (生产)

部署
Docker + Docker Compose

Nginx (反向代理)

4. 数据库设计
4.1 PostgreSQL 表结构
sql
-- 用户表
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    hashed_password VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 文件表
CREATE TABLE files (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    filename VARCHAR(255) NOT NULL,
    file_type VARCHAR(50), -- pdf, image, audio, text
    file_path VARCHAR(500), -- 本地存储路径
    file_size BIGINT,
    status VARCHAR(20) DEFAULT 'pending', -- pending, processing, completed, failed
    chunk_count INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 聊天记录表 (可选)
CREATE TABLE conversations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    question TEXT NOT NULL,
    answer TEXT,
    file_ids UUID[], -- 引用的文件ID列表
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

GET	/api/files/{file_id}/status	查询处理状态	JWT
上传接口细节:

http
POST /api/files/upload
Content-Type: multipart/form-data
Authorization: Bearer <token>

参数:
- file: <二进制文件>
- file_type: "pdf" | "image" | "audio" | "text"

响应 (202 Accepted):
{
    "file_id": "uuid",
    "status": "processing",
    "message": "文件已上传，后台处理中..."
}
5.3 对话接口
方法	路径	描述	权限
POST	/api/chat/query	普通问答 (非流式)	JWT
GET	/api/chat/stream	流式问答 (SSE)	JWT
流式接口细节:

http
GET /api/chat/stream?question=总结这份PDF说了什么&file_ids=uuid1,uuid2
Authorization: Bearer <token>

响应 (text/event-stream):
data: {"type": "start", "chunk": ""}
data: {"type": "content", "chunk": "这"}
data: {"type": "content", "chunk": "份"}
data: {"type": "content", "chunk": "文"}
... 
data: {"type": "end", "sources": ["file1.pdf", "file2.pdf"]}
5.4 摘要接口
方法	路径	描述	权限
POST	/api/summarize	生成指定文件的摘要	JWT

6.3 流式输出实现
python
# api/chat.py

@router.get("/stream")
async def stream_chat(
    question: str,
    file_ids: List[str] = Query(...),
    current_user: User = Depends(get_current_user)
):
    async def generate():
        # 1. 检索上下文
        context = retrieve_context(question, file_ids)
        
        # 2. 流式调用LLM
        async for chunk in llm.astream(generate_prompt(question, context)):
            yield f"data: {json.dumps({'type': 'content', 'chunk': chunk})}\n\n"
        
        # 3. 结束标记
        yield f"data: {json.dumps({'type': 'end'})}\n\n"
    
    return StreamingResponse(generate(), media_type="text/event-stream")

8. 开发排期 (4周冲刺)
周次	任务	交付物
第1周	环境搭建 + 基础CRUD	Docker-compose跑通，用户注册/登录API，文件上传下载
第2周	AI能力集成	PDF解析 + ChromaDB存入 + 基础RAG问答 (非流式)
第3周	前端开发 + 流式输出	Next.js界面 + SSE流式对话 + 文件管理页面
第4周	多模态扩展 + 部署	音频转文字、图片理解、Docker部署上线
9. 技术难点与解决方案
难点	解决方案	优先级
大文件上传超时	前端分片上传 + 后端异步任务 (Celery)	高
向量检索性能	ChromaDB索引优化 (默认已支持)	中
长文档切片策略	语义切片 (SemanticChunker) + 重叠窗口	高
流式输出稳定性	FastAPI StreamingResponse + 心跳机制	高
多模态统一检索	图片/音频 → 文本描述 → 统一向量化	中
LLM幻觉问题	加入系统提示 + 引用来源标注	中
